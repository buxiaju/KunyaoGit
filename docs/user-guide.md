## 1. 首次启动与初始化配置

### 1.1 应用界面总览

启动 KunyaoGit 后，你会看到左侧导航栏和右侧主内容区。左侧导航包含：

| 导航项 | 说明 |
|--------|------|
| 首页 | 欢迎页与最近打开的仓库列表 |
| GitHub | 浏览/管理你的 GitHub 仓库 |
| Gitee | 浏览/管理你的 Gitee（码云）仓库 |
| Release | 为当前仓库创建/管理版本发布 |
| 设置 | 配置 Git 路径、Token、默认克隆目录等 |

导航栏顶部有「打开仓库」按钮，底部显示已连接的 GitHub / Gitee 账号。

### 1.2 设置 Git 可执行路径

KunyaoGit 通过调用本地 Git 命令行完成所有操作，首次使用前请确认 Git 已安装并可用。

1. 点击左侧导航的「设置」。
2. 在「通用」区块找到 **Git 可执行文件路径**。
3. 留空表示使用系统 `PATH` 中的 `git`；若 Git 未在 PATH 中，可手动填写完整路径，例如：
   ```
   C:\Program Files\Git\bin\git.exe
   ```
4. 点击「选择」按钮可弹出输入框填入路径。
5. 点击「测试」按钮，出现 `✅ OK` 及版本号表示配置成功；若显示 `失败`，请检查路径或重新安装 Git。
6. 点击「保存」使配置生效。

> **提示**：Windows 下安装 Git for Windows 时，勾选「Add to PATH」选项可自动将 git 加入系统 PATH，无需手动填写路径。

### 1.3 配置 GitHub Token

Token 用于访问 GitHub 仓库列表、在线编辑远程文件、创建 Release 等功能，存储于本地（electron-store），不会上传。

1. 在浏览器打开 https://github.com/settings/tokens （GitHub Settings → Developer settings → Personal access tokens）。
2. 点击「Generate new token」创建令牌，勾选以下最小权限：
   - `repo`（访问私有仓库需要）
   - `read:user`
   - 不需要勾选 `admin:org`、`delete_repo` 等敏感权限。
3. 复制生成的令牌（形如 `ghp_...`）。
4. 回到 KunyaoGit → 设置 → **GitHub** 区块，将令牌粘贴到「Personal Access Token」输入框。
5. 点击右侧眼睛图标可切换令牌明文/隐藏显示。
6. 点击「测试并保存」。验证通过后会提示 `已连接：@你的用户名`，区块右上角显示绿色对勾与用户名。

> **断开连接**：已配置状态下点击用户名旁的「断开」即可清除 Token。

### 1.4 配置 Gitee Token

1. 在浏览器打开 https://gitee.com/personal_access_tokens （Gitee 设置 → 私人令牌）。
2. 生成令牌，建议勾选权限：`projects`、`pull_requests`、`issues`。
3. 复制令牌。
4. 回到 KunyaoGit → 设置 → **Gitee** 区块，粘贴令牌到「私人令牌」输入框。
5. 点击「测试并保存」，验证通过后显示 `已连接：@你的用户名`。

### 1.5 设置默认克隆目录

在「设置 → 通用 → 默认克隆目录」中填入或通过「浏览」按钮选择一个目录（如 `D:\Projects`）。配置后，从 URL 克隆仓库时会自动使用该目录作为目标，无需每次手动选择。

## 2. 仓库管理

### 2.1 打开本地仓库

1. 在首页或侧边栏点击「打开本地仓库」（或侧边栏顶部的「打开仓库」按钮）。
2. 在弹出的文件夹选择对话框中，定位到本地 Git 仓库根目录并确认。
3. 仓库打开后自动进入仓库页面，顶部显示仓库名、路径和当前分支。

**最近打开列表**：首页会记录最近打开过的仓库卡片，显示仓库名、路径、当前分支及最后打开时间。

- 单击卡片可重新打开该仓库。
- 鼠标悬停卡片右上角会出现两个按钮：
  - 外链图标：在系统文件管理器中打开该仓库目录。
  - × 图标：仅从最近列表移除（不会删除本地文件）。

### 2.2 从 URL 克隆

1. 在首页点击「克隆仓库」按钮，展开克隆面板。
2. 在输入框中粘贴仓库地址，支持 HTTPS 与 SSH 格式，例如：
   ```
   https://github.com/owner/repo.git
   git@gitee.com:owner/repo.git
   ```
3. 点击「克隆」（或按回车键）。
4. 若已设置默认克隆目录，将直接克隆到该目录下的同名子目录；若未设置，会弹出对话框让你选择目标目录。
5. 克隆成功后提示 `克隆成功：路径`，并自动打开该仓库。

> 若未配置默认克隆目录，面板下方会提示「未设置默认克隆目录」，建议前往设置页配置。

### 2.3 初始化新仓库

如需将一个尚未纳入 Git 管理的本地目录初始化为新仓库：

1. 点击「打开本地仓库」，选择目标目录。
2. 应用会检测到该目录不是 Git 仓库，并提供初始化选项（创建 `git init`）。
3. 初始化完成后即可正常进行提交等操作。

### 2.4 仓库页面结构

打开仓库后，顶部工具栏提供以下操作：

| 按钮 | 功能 |
|------|------|
| ← 返回 | 回到首页 |
| 导入 | 选择本地文件/文件夹导入到仓库（也可直接拖拽） |
| ⟳ 刷新 | 刷新仓库状态 |
| Fetch | 从远程获取最新引用（不合并） |
| 拉取 | 拉取远程更新并合并到当前分支 |
| 推送 | 将本地提交推送到远程 |

顶部还会显示当前分支名，并标注与远程的差异：`↑N` 表示领先 N 个提交，`↓N` 表示落后 N 个提交。

下方为 Tab 栏，包含五个标签页：

| Tab | 说明 |
|-----|------|
| 变更 | 查看工作区改动、暂存、提交 |
| 历史 | 提交历史时间线 |
| 分支 | 分支创建/切换/删除/合并 |
| 远程 | 远程仓库信息 |
| 文件 | 仓库文件树浏览与编辑 |

## 3. Git 日常操作

### 3.1 查看变更

切换到「变更」Tab，左侧为变更面板，右侧为 Diff 视图。

- 变更面板分为两个区域：
  - **已暂存**：已 `git add` 进入暂存区的文件。
  - **变更**：工作区有改动但尚未暂存的文件。
- 每个文件前有状态图标与颜色标记：

| 状态 | 含义 | 颜色 |
|------|------|------|
| 新增 (added) | 新增文件 | 绿色 |
| 修改 (modified) | 内容已修改 | 琥珀色 |
| 删除 (deleted) | 文件已删除 | 红色 |
| 重命名 (renamed) | 文件被重命名 | 紫色 |
| 未跟踪 (untracked) | 尚未被 Git 管理 | 灰色 |
| 冲突 (conflicted) | 存在合并冲突 | 红色 |

- 单击文件可在右侧 Diff 视图查看具体改动内容，顶部显示 `+新增行数 / -删除行数`。
- 二进制文件会显示「二进制文件，无法显示 diff」。

### 3.2 暂存 / 取消暂存

- **暂存单个文件**：点击文件前的方框，使其由空心变为勾选状态，即执行 `git add`。
- **取消暂存**：点击已暂存文件的方框，取消勾选，即执行 `git reset`。
- **全部暂存**：在「变更」区域标题右侧点击「全部暂存」。
- **全部取消暂存**：在「已暂存」区域标题右侧点击「全部取消暂存」。

### 3.3 丢弃修改

对于已修改（非未跟踪、非冲突）的文件，鼠标悬停文件行时右侧会出现回退图标（⟲）：

1. 点击回退图标。
2. 在确认对话框中点击「确定」。
3. 该文件的本地修改将被丢弃（`git checkout`），不可恢复，请谨慎操作。

### 3.4 提交

1. 在变更面板底部「提交信息...」文本框中填写提交说明。
2. 确认上方已暂存所需文件（底部会显示「N 个文件已暂存」）。
3. 点击「提交」按钮完成提交（`git commit`），成功后提示 `已提交：提交哈希前7位`。

### 3.5 提交并推送

若希望一步完成提交与推送：

1. 填写提交信息并暂存文件。
2. 点击「提交并推送」按钮（带上传图标）。
3. 应用先执行提交，成功后自动推送到远程，分别提示 `已提交` 与 `已推送到远程`。

### 3.6 推送 / 拉取 / Fetch

使用仓库顶部工具栏的按钮：

- **Fetch**：从远程获取最新引用与对象，但不修改本地分支。适合先了解远程是否有更新。成功提示 `已 fetch`。
- **拉取**：执行 `git pull`，获取远程更新并合并到当前分支。成功提示 `拉取成功`。
- **推送**：执行 `git push`，将本地提交上传到远程。成功提示 `推送成功`。

操作失败时会以红色 Toast 提示具体错误信息（如认证失败、非快进等）。

### 3.7 导入本地文件 / 拖拽上传

KunyaoGit 支持将本地文件或文件夹快速导入到当前仓库并自动暂存，**完整保留目录结构**。

**方式一：拖拽上传**

1. 打开仓库页面。
2. 直接将系统文件管理器中的文件或文件夹拖入应用窗口。
3. 窗口会出现绿色虚线覆盖层，提示「松开以导入文件」。
4. 松开鼠标后，文件会被复制到仓库对应路径并自动 `git add`，成功提示 `已导入 N 个文件并暂存`。

**方式二：按钮导入**

1. 点击仓库顶部工具栏的「导入」按钮。
2. 在文件选择对话框中选择文件（支持多选，选择文件夹时保留其内部结构）。
3. 确认后即开始导入与暂存。

> 导入的文件会出现在「变更」面板的已暂存区，可直接提交。

### 3.8 查看提交历史

切换到「历史」Tab，以时间线形式展示提交记录，每条提交显示：

- 提交哈希、作者、提交时间
- 提交信息
- Tag 与分支引用标记

## 4. 分支管理

切换到仓库页面的「分支」Tab。

### 4.1 查看分支

- **本地分支**：上方列表展示所有本地分支，当前分支以绿色图标和高亮显示，并标注 `↑N`（领先）/ `↓N`（落后）远程的提交数。
- **远程分支**：下方列表展示远程分支（紫色图标）。

### 4.2 创建分支

1. 点击「本地分支」标题右侧的「新建分支」按钮。
2. 在弹出的输入框中填写新分支名。
3. 点击「创建」（或按回车），成功后提示 `已创建分支 名称`。

新分支基于当前分支创建。

### 4.3 切换分支

- **本地分支**：点击目标分支行的对勾图标（✓）即可切换（`git checkout`），成功提示 `已切换到 分支名`。
- **远程分支**：点击远程分支行，会自动检出对应的本地分支。

### 4.4 合并分支

将其他分支合并到当前分支：

1. 确保当前停留在目标分支（即合并的「接受方」）。
2. 在其他分支行点击合并图标（GitMerge）。
3. 成功提示 `已合并 分支名`；若产生冲突，请参考下一节解决。

### 4.5 删除分支

1. 点击目标分支行的垃圾桶图标。
2. 在确认对话框中点击「确定」。
3. 删除成功后提示 `已删除`。

> 当前所在分支不可删除，且删除操作会使用强制删除（`git branch -D`）。

## 5. 冲突解决

当合并、拉取或变基产生冲突时，冲突文件会以红色「冲突」状态出现在变更面板的「变更」区域。

冲突文件行右侧会出现两个一键解决按钮：

| 按钮 | 含义 | 说明 |
|------|------|------|
| `ours` | 保留当前分支版本 | 采用本地（当前分支）的内容，丢弃传入分支的改动 |
| `theirs` | 采用传入分支版本 | 采用远程/传入分支的内容，丢弃本地的改动 |

操作步骤：

1. 在变更列表找到标记为「冲突」的文件。
2. 根据需要点击 `ours` 或 `theirs`。
3. 成功后提示 `已接受 当前分支/传入分支 版本`，文件自动转为已暂存状态。
4. 所有冲突解决后，即可正常提交完成合并。

> 这是「一键解决」策略，适用于整文件采用一方版本的场景。如需逐行手动解决，请在外部编辑器处理后回到应用暂存。

## 6. 远程仓库浏览

通过左侧导航的「GitHub」或「Gitee」进入对应平台的远程仓库列表页。

### 6.1 浏览仓库列表

进入后顶部显示平台名称与已连接的用户名。仓库以卡片网格展示，每张卡片包含：

- 仓库名（私有仓库显示锁图标，公开仓库显示开锁图标）
- 描述
- 编程语言、Star 数、Fork 数、默认分支、最后更新时间
- 外链图标：在浏览器中打开该仓库主页

卡片右侧提供操作按钮：
- **查看**：进入仓库详情页。
- **克隆**：直接克隆到本地默认克隆目录并打开。
- **删除**：删除远程仓库（需二次确认，仅对本人仓库有效）。

点击「新建仓库」按钮可在该平台创建新仓库：填写仓库名（仅字母、数字、`._-`）、描述，勾选「私有仓库」「初始化 README」后点击「创建」。

点击「刷新」可重新拉取列表。页面顶部还提供**搜索框**（带放大镜图标），输入关键词即可搜索或过滤仓库，详见 [13. 云端仓库搜索](#13-云端仓库搜索)。

### 6.2 仓库详情页

点击卡片或「查看」按钮进入详情页，顶部显示 `平台 / owner / repo` 路径，并提供「浏览器打开」「克隆到本地」按钮。

详情页包含三个 Tab：

| Tab | 说明 |
|-----|------|
| PR | 查看 Pull Request 列表（可按 开启/关闭/全部 筛选），点击在浏览器打开 |
| Issue | 查看 Issue 列表（可按状态筛选），点击在浏览器打开 |
| 文件 | 在线浏览、编辑远程仓库文件 |

### 6.3 在线编辑远程文件

切换到「文件」Tab，左侧为远程文件树，右侧为 Monaco Editor（VS Code 同款编辑器）。

**浏览文件**：

- 点击文件夹进入子目录，顶部面包屑可点击跳转任意层级。
- 点击文件即在右侧加载内容（根据扩展名自动识别语言高亮）。
- 二进制文件会提示「不支持在线编辑」。

**编辑并保存**：

1. 选中文件后点击右上角「编辑」按钮进入编辑模式（标题旁出现橙色圆点）。
2. 在编辑器中修改内容。
3. 在底部输入框填写「提交说明」（必填）。
4. 点击「保存到远程」，应用通过 Contents API 直接提交修改到远程仓库，成功提示 `已保存到远程`。
5. 点击「取消」可放弃编辑（恢复原内容）。

**新建文件**：

1. 点击文件树顶部「+」按钮。
2. 在输入框填写文件名（如 `README.md`）。
3. 点击「建」，文件即在当前目录创建并自动打开进入编辑。

**删除文件**：

1. 选中文件后点击右上角垃圾桶图标。
2. 确认删除并在底部填写提交说明。
3. 点击保存即从远程删除该文件。

### 6.4 拖拽上传

在仓库页面的本地文件 Tab（「文件」Tab）中，支持将本地文件拖拽到仓库窗口进行导入上传，详见 [3.7 导入本地文件 / 拖拽上传](#37-导入本地文件--拖拽上传)。

## 7. Release 版本管理

通过左侧导航「Release」进入版本发布页（需先打开一个本地仓库）。

> v0.6 起本页大幅增强：**附件上传 / 下载 / 删除**、**Release 编辑**、**详情抽屉（Markdown 渲染）**、**列表搜索**、**发布草稿**。

### 7.1 平台切换

页面右上角提供 GitHub / Gitee 平台切换按钮，选择在哪个平台管理 Release。切换后自动加载该平台对应仓库的 Release 列表。

> 使用前请确保已在「设置」中配置对应平台的 Token，否则会提示「未配置 GitHub Token / Gitee Token」。

### 7.2 查看 Release 列表

列表展示已有的 Release，每条卡片显示：

- Release 名称与 Tag（如 `v1.0.0`）
- 状态标签：草稿（灰色）、预发布（琥珀色）、平台标识
- 发布时间与附件数量
- 右侧操作按钮：**发布草稿**（仅 GitHub draft 时出现）、**删除**、**详情**（`>` 图标）

点击垃圾桶图标可删除该 Release（需确认）。

### 7.3 搜索 Release（v0.6）

顶部搜索框支持按 **Tag 或名称**实时过滤：

- 输入 `v0.5` → 命中 Tag 含 `v0.5` 的所有 Release
- 输入名称片段 → 按 Release 标题匹配
- 无匹配时显示「没有匹配的 release」；清空搜索词恢复完整列表

旁边的刷新按钮可手动重新拉取列表。

### 7.4 创建 Release（含附件上传，v0.6）

1. 点击右上角「新建 Release」按钮，展开创建表单。
2. 填写 **Tag**（如 `v1.0.0`）和 **Release 名称**（两者必填，为空时点创建会提示）。
3. 勾选选项：
   - **草稿**：保存为草稿，不公开发布（仅 GitHub 支持，Gitee 下此选项禁用）。
   - **预发布**：标记为预发布版本。
4. 在下方文本框填写 Release 描述（支持 Markdown）。
5. **添加附件（v0.6 新增）**：
   - 点击附件区的「添加附件」按钮，弹出系统文件对话框（**支持多选**）。
   - 选中的文件出现在待上传列表，显示文件名；点右侧 `×` 可移除。
   - Gitee 平台下若添加了 ≥100MB 的文件，会出现琥珀色提示「Gitee 单附件上限约 100MB，建议使用 GitHub」。
6. 点击「创建」提交。执行顺序是**先创建 Release，再逐个上传附件**：
   - 全部成功 → 提示「已创建 Release 并上传 N 个附件」
   - 部分失败 → 失败项单独告警，最终提示「已创建 Release，N/M 个附件上传成功」

> **附件大小限制**：GitHub 单文件软限约 2GB；Gitee 单文件 ≤ 100MB。大文件建议发到 GitHub。
>
> **无进度条**：v0.6 上传期间只显示「上传中」状态，不显示百分比进度（大文件场景的进度条是后续候选）。

### 7.5 Release 详情抽屉（v0.6）

点击任意 Release 卡片右侧的「详情」按钮（`>` 图标），从右侧滑出 640px 宽的详情抽屉：

**头部**：Tag / 名称 / 状态徽标（草稿 / 预发布 / 平台）/ 发布时间

**描述区**：使用 `marked` 渲染完整 Markdown —— 标题、列表、代码块、链接都会正确排版（此前只能看纯文本）。描述为空时显示「（无描述）」。

**附件区**：每个附件一行，显示文件名、大小、下载次数，并提供两个操作：

| 操作 | 说明 |
|------|------|
| 下载（⬇ 图标） | 用系统默认方式下载该附件 |
| 删除（🗑 图标） | 二次确认后从 Release 移除该附件 |

**上传新附件**：附件区右上角「上传新附件」按钮，可对**已发布的 Release** 继续追加附件，上传后列表自动刷新。

按 `Esc` 或点击右上角 `✕` 关闭抽屉。

### 7.6 编辑 Release（v0.6）

在详情抽屉底部点击「编辑」进入编辑模式：

1. **名称**：输入框直接修改
2. **描述**：textarea 编辑 Markdown 原文
3. **预发布**：复选框切换
4. 点击「保存修改」提交 → 提示「已更新 Release」，抽屉切回查看模式并显示新内容
5. 编辑模式下按 `Esc` 取消（不保存，恢复原内容）

> **平台差异**：GitHub 支持修改 name / body / prerelease / draft；Gitee 支持 name / body / prerelease，**不支持 draft 切换**（Gitee 没有草稿概念，创建即发布）。

### 7.7 发布草稿（v0.6，仅 GitHub）

GitHub 上创建的草稿 Release 可以一键转为正式发布：

- **入口一**：列表卡片上的「发布草稿」按钮（📤 图标，仅 draft 状态出现）
- **入口二**：详情抽屉底部的「发布草稿」按钮

点击后提示「已发布」，草稿徽标消失。

> Gitee 没有草稿状态，因此不会出现该按钮。

### 7.8 从 commits 自动生成 CHANGELOG

1. 在创建表单中点击「从 commits 自动生成 CHANGELOG」按钮。
2. 应用会扫描仓库的提交历史，遵循 **Conventional Commits** 规范，按类型分组生成变更日志，例如：
   - `feat`：新功能
   - `fix`：Bug 修复
   - `docs`：文档
   - `refactor`：重构
   - `perf`：性能优化
   - `chore`：杂项
3. 生成内容会自动填入描述文本框，可在此基础上编辑调整。
4. 点击「创建」提交 Release，成功提示 `已创建 Release`。

## 8. 应用内自动更新

> v0.2.2 引入自动下载安装；v0.2.4 大幅提速（4 路并发，3~6 倍）；v0.2.6 修复部分网络下探活失败；v0.3.1 起 Gitee 下载源改为 Release 附件；v0.3.3 起下载失败自动重试。

### 8.1 启动自动检查

KunyaoGit 在每次启动后会**静默检查** GitHub 与 Gitee 两个平台的最新 Release：

- 启动后约 **1.5 秒**开始检查（给主进程留出初始化时间）。
- 主进程对检查做了 **6 小时节流**，避免频繁请求。
- 同时请求 GitHub 和 Gitee，取两者中**版本号更高**的作为最新版本。
- 检查失败会**静默忽略**，不打扰用户。

### 8.2 发现新版本弹窗

当检测到新版本且未被忽略时，会自动弹出「发现新版本」对话框，显示：

- 新版本号与当前版本号
- Release 发布说明（Markdown 文本）

对话框提供三个操作：

| 按钮 | 功能 |
|------|------|
| 立即下载并安装 | 开始应用内下载（见 8.3） |
| 稍后 | 关闭弹窗，本次不更新 |
| 浏览器打开 | 在系统浏览器打开 Release 页面手动下载 |

> 弹出一次后该版本会被标记为已忽略，避免同一会话或下次启动重复弹出。你仍可在「设置 → 关于」中手动检查。

### 8.3 应用内下载与安装（v0.2.4+ 提速）

点击「立即下载并安装」后：

1. 对话框切换到下载进度界面，显示：
   - 当前下载源（GitHub / Gitee）
   - 进度百分比与进度条
   - 已下载字节数 / 总字节数（若服务器未返回大小则显示「大小未知」，进度条以脉冲动画表示）
   - **★ 瞬时下载速率**（如 `4.2 MB/s`），实时显示
2. 下载完成后，界面显示「下载完成」，并提示「正在启动安装程序，应用将自动退出以完成更新…」。
3. 应用自动退出并启动 NSIS 安装程序，按提示完成安装即可升级到新版本。

> 内部实现：v0.2.4+ 用 4 路并发 HTTP Range 下载（实测 90MB 从单连接 18s 降到 4-6s），同时复用 keep-alive Agent 省去重复 TLS 握手，进度事件按 100ms 节流避免 IPC 通道被刷爆。

> **v0.3.1+**：Gitee 下载源改为使用 **Release 附件**（Assets），避免此前 raw 文件在大文件时受限的问题。

### 8.4 取消下载

下载过程中可点击「取消」按钮中止下载，对话框回到询问状态，可稍后重试或改用浏览器下载。

> 直接点击对话框遮罩层关闭窗口时，若处于下载中也会自动取消下载。

### 8.5 下载失败处理（v0.2.6+ 更友好）

若下载失败，对话框会显示「下载失败」及**所有源的失败原因**（v0.2.6 之前只显示最后一个错的源）：

> 例：`所有下载源都失败：github（请求失败（超时/网络））; gitee（Gitee raw 返 HTML（大文件受限））`

并提供：

- **重试**：重新尝试下载（再次并行探活所有源）。
- **浏览器下载**：跳转浏览器手动下载安装包。

**v0.2.6 探活修复**：用 `Range: bytes=0-0` GET 替代 HEAD（部分 CDN/防火墙对 HEAD 直接 403/超时），超时从 8s 提到 15s。

> **v0.3.3+ 自动重试**：下载过程中若出现网络波动，应用会自动重试，最多约 **2 分钟**，界面显示「网络波动，第 N/6 轮重试…」，不再一失败就报错。若下载持续失败，可点击「浏览器下载」，或手动下载安装包（见安装指南）。

### 8.6 手动检查更新

1. 进入「设置」页，滚动到底部「关于」区块。
2. 显示当前版本号（如 `KunyaoGit v0.6.3`）。
3. 点击「检查更新」按钮。
4. 检查结果会以彩色卡片显示：
   - 发现新版本：琥珀色卡片，显示新版本号、来源平台、Release 说明，并提供「立即下载并安装」「浏览器打开」「忽略此版本」按钮。
   - 已是最新：绿色卡片提示。
5. 卡片下方还会列出两个平台的检查明细（✓ 成功 / ✕ 失败 及对应版本或错误）。

### 8.7 忽略版本

在「设置 → 关于」的更新卡片中点击「忽略此版本」：

- 该版本不再触发自动弹窗提示。
- 后续若有更高版本发布仍会正常提示。

## 9. 设置页功能

点击左侧导航「设置」进入设置页。页面由以下几个区块组成：

### 9.1 通用

| 配置项 | 说明 |
|--------|------|
| Git 可执行文件路径 | 本地 git.exe 的完整路径，留空则使用系统 PATH 中的 git。可点击「选择」填写，点击「测试」验证是否可用 |
| 默认克隆目录 | 从 URL 克隆时的默认目标目录，避免每次手动选择 |

填写后点击「保存」生效。测试结果会以绿色（成功，显示版本号）或红色（失败）文字显示。

### 9.2 GitHub / Gitee Token 管理

- **GitHub**：填入 Personal Access Token，点击「测试并保存」验证并存储。配置成功后显示绿色对勾与 `@用户名`。
- **Gitee**：填入私人令牌，点击「测试并保存」验证并存储。
- 两者均支持点击眼睛图标切换明文/隐藏显示。
- 已配置状态下点击「断开」可清除对应平台的 Token。
- Token 安全存储于本地 electron-store，不会上传服务器。

详细权限要求见 [1.3 配置 GitHub Token](#13-配置-github-token) 与 [1.4 配置 Gitee Token](#14-配置-gitee-token)。

### 9.3 关于

- 显示应用名称与当前版本号。
- 「检查更新」按钮用于手动触发更新检查，详见 [8.6 手动检查更新](#86-手动检查更新)。
- 显示应用构建技术栈说明（Electron + React + TypeScript）。

### 9.4 主题、Diff 视图与界面语言

KunyaoGit 的应用设置中包含以下可配置项，影响显示效果：

| 配置项 | 可选值 | 默认值 | 说明 |
|--------|--------|--------|------|
| 主题 (theme) | `dark` / `ocean` / `light` | `dark` | ★ v0.2.5：界面主题（暗色 / 深蓝 / 亮色），详见 §10 |
| 语言 (language) | `zh` / `en` | `zh` | ★ v0.2.3：界面语言（中/英切换），详见 §10 |
| Diff 视图模式 (diffView) | `split` / `unified` | `split` | 控制变更面板右侧 Diff 视图的渲染方式 |

**Diff 视图模式差异**：

- **并排模式 (split)**：左右两列对比，左侧为修改前内容（删除行红色），右侧为修改后内容（新增行绿色），便于直观对比同一位置的变化。
- **统一模式 (unified)**：单列显示，按顺序展示上下文行、删除行（红色 `-`）与新增行（绿色 `+`），类似 `git diff` 命令行输出。

Diff 视图顶部会显示文件路径、行数增减统计，二进制文件会提示无法显示。

## 10. 界面主题与语言切换

### 10.1 三主题切换（v0.2.5+）

KunyaoGit 提供 3 套 UI 主题，在「设置 → 主题」区域切换：

| 主题 | 主色 | 适合场景 |
| --- | --- | --- |
| **暗色**（默认） | 🟢 Emerald 绿 | 长时间编码护眼、夜晚使用 |
| **深蓝** | 🔵 Blue 蓝 | 想要点色彩又稳重的氛围 |
| **亮色** | 🟢 Emerald 绿 | 白天 / 投影 / 截图分享 |

**操作步骤**：

1. 进入「设置」页。
2. 在「主题」一栏看到 3 个色卡按钮（每个按钮带该主题的代表色）。
3. 点击任意色卡 → 全 UI 立即切换（背景、面板、按钮、边框、Monaco 编辑器都跟随）。
4. 主题自动持久化到本地 electron-store，重启应用后保留。

**实现细节**（技术向可选）：

- 通过 `<html data-theme="dark|ocean|light">` 切换 CSS 变量。
- Tailwind 的 `bg-gray-XXX` 等类不需改一行，由 `[data-theme] .bg-gray-XXX { background-color: var(--bg-app) }` 这类选择器覆盖。
- Monaco 编辑器通过 `kg-theme-change` CustomEvent 监听，同步调用 `monaco.editor.setTheme('vs-dark' | 'vs')`。

### 10.2 中英双语切换（v0.2.3+）

「设置 → 语言」或侧边栏底部均可切换：

- **中文**（默认）：所有界面文案为简体中文
- **English**：所有界面文案切换为英文

切换即时生效，无需重启。同样持久化到 electron-store。

## 11. 本地文件管理（新增/修改/删除仓库内文件）

打开本地仓库后，切换到「文件」Tab 即可浏览并管理仓库内的文件与文件夹，所有改动都会自动同步到 Git 状态。

### 11.1 浏览文件树

- 左侧为文件树，展示仓库内的全部文件与文件夹；**默认全部折叠**，点击文件夹前的箭头即可展开。
- 工具栏提供「新建文件」「新建文件夹」「刷新」三个按钮。

### 11.2 新建文件 / 新建文件夹

1. 点击工具栏的「新建文件」或「新建文件夹」按钮。
2. 新建文件会**直接打开 Monaco 编辑器**，填写内容后保存即可。
3. 保存后自动刷新「变更」页，新文件以「新增」状态出现在变更列表中，可继续暂存与提交。

> 也可在文件或文件夹上右键，选择「新建文件」或「新建文件夹」，此时创建在**当前目录**下。

### 11.3 编辑文件

1. 在文件上右键，选择「在编辑器中打开」（或直接双击文件）。
2. 文件内容加载到右侧 Monaco 编辑器，按扩展名自动识别语言高亮。
3. 修改后保存，改动自动同步到「变更」页（修改状态），可继续暂存与提交。

### 11.4 重命名 / 删除

- **重命名**：在文件或文件夹上右键选择「重命名」，输入新名称确认。
- **删除**：在文件或文件夹上右键选择「删除」，确认后移除。
- 重命名/删除同样**自动同步 Git 状态**：「变更」页会对应显示重命名（renamed）或删除（deleted）状态。

## 12. 推送到指定远程（GitHub / Gitee）

当仓库配置了多个远程（如同时关联 GitHub 与 Gitee）时，可手动选择把当前分支推送到指定平台。

### 12.1 选择推送目标

1. 打开仓库页，在顶部右侧「Push」按钮旁点击**下拉箭头**。
2. 下拉列表会显示所有已配置的远程，并按平台区分图标：
   - **GitHub** 仓库：灰色 GitHub 图标
   - **Gitee** 仓库：红色 Gitee 图标
   - 其他远程：分支图标
3. 选择「推送到 github」或「推送到 gitee」，应用会把当前分支推送到该平台并**自动建立跟踪关系**。

### 12.2 首次推送与后续推送

- **首次**把某分支推送到某远程时，需要通过下拉菜单指定目标远程。
- 之后直接点击「Push」按钮，即可推送到**上次的跟踪远程**，无需再次选择。

### 12.3 「提交并推送」选择远程

「变更」页的「提交并推送」按钮同样支持下拉选择目标远程，可一步完成提交与推送。

### 12.4 尚未配置远程

若仓库还没有远程，请先切换到「远程」Tab 添加远程（远程页提供添加/删除入口），再按上述步骤推送。

## 13. 云端仓库搜索

### 13.1 打开搜索

1. 点击左侧导航的「GitHub」或「Gitee」，进入对应平台的仓库列表页。
2. 页面顶部出现**搜索框**（带放大镜图标）。

### 13.2 输入关键词自动搜索

- 输入关键词（如仓库名）即**自动搜索**，无需按回车：
  - **GitHub**：搜索**全平台**仓库（GitHub Search API）。
  - **Gitee**：因官方搜索接口限制，会在**你的仓库列表**中按名称/描述过滤。
- 点击搜索框右侧的 **✕**，或清空输入文字，即可恢复「我的仓库」列表。

### 13.3 搜索结果操作

搜索结果的卡片与普通仓库卡片一致，可：

- **打开**：进入仓库详情页浏览文件
- **克隆**：克隆到本地（默认克隆目录）
- **删除**：删除远程仓库（需二次确认）

## 15. Stash 队列管理（v0.4）

v0.4 起，stash 从"只能 push / pop 最新"升级为完整队列管理。

### 15.1 入口

仓库页 → **变更 Tab** → 顶部 **"Stash 队列"** 折叠面板（默认收起，点击展开）。

### 15.2 操作

- **保存当前修改**：点击右上角 "+" → 输入可选描述 → 确认
- **应用（保留）**：把 stash 应用到工作区，stash 仍在队列
- **应用并移除**：等于「应用 + 删除」
- **查看 diff**：弹窗显示该 stash 包含的文件变更
- **删除**：二次确认后从队列移除

> **v0.3 旧版用户**：升级到 v0.4 后，已有的 stash 会自动出现在新面板中，零迁移。

### 15.3 典型场景

| 场景 | 操作 |
|---|---|
| 切分支前保留改动 | 顶部 `+` → 输入描述「修复中」→ 切分支 → 回来后"应用（保留）" |
| 实验性修改 | 改了一通 → `+` stash → 切回稳定分支 → 后悔了 → 列表里点"应用" |
| 永久丢弃 stash | 列表里点删除图标 → 确认 |

## 16. Cherry-pick / Revert（v0.4）

v0.4 起，提交历史支持"拣一个 commit"和"回退一个 commit"。

### 16.1 入口

仓库页 → **历史 Tab** → 鼠标悬停任意 commit 行 → 右侧出现 3 个小图标：

- 📋 **复制 SHA**：复制完整哈希到剪贴板
- 🔀 **Cherry-pick**：把该 commit 应用到当前分支
- ↶ **Revert**：生成一个反向 commit（红色按钮表示危险）

### 16.2 Cherry-pick 流程

1. 悬停 commit → 点击 🔀
2. 弹窗显示：commit hash + 作者 + 主题
3. 点击"确认" → 应用到当前分支
4. 成功 toast 包含新 commit hash
5. 冲突时 toast 黄色提示「请在变更页解决」

### 16.3 Revert 流程

1. 悬停 commit → 点击 ↶（红色）
2. 弹窗带黄色警告条（提示会修改历史）
3. 确认 → 生成反向 commit 并自动 commit
4. 冲突时同上

### 16.4 适用场景

| 场景 | 操作 |
|---|---|
| 把 hotfix 同步到 main | 历史 → 找到 hotfix commit → Cherry-pick |
| 撤销一次错误提交 | 历史 → 找到错误 commit → Revert |
| 想知道 commit 完整 hash | 历史 → 悬停 → 📋 复制 |

## 17. 创建 PR / MR（v0.4）

v0.4 起，从"只能看 PR"升级到"应用内创建 PR / MR"。

### 17.1 入口

仓库页 → **分支 Tab** → 当前分支行（当 `ahead > 0` 且存在 GitHub / Gitee remote 时，行尾显示 `<GitPullRequest>` 图标按钮）→ 点击打开创建对话框。

> 如果看不到按钮，请检查：
> 1. 当前分支是否比远程多 N 个提交（ahead > 0）
> 2. 是否在「远程」标签添加了 GitHub 或 Gitee 远程地址

### 17.2 弹窗流程

1. **选平台**：自动选中第一个 GitHub / Gitee remote（多 remote 时可切换）
2. **填标题**：默认取最后一次 commit message
3. **填描述**：Markdown 支持
4. **目标分支（base）**：自动拉取仓库默认分支（如 `master` / `main`），可手动改
5. **GitHub Only**：可勾选"创建为草稿"
6. 点"创建 PR" → 成功后弹成功页（含链接 + "在浏览器打开"按钮）

### 17.3 适用场景

| 场景 | 操作 |
|---|---|
| 完成 feature 分支 | 分支 → 当前分支 → 创建 PR |
| 提紧急 hotfix 到生产 | 分支 → 切到 hotfix → 创建 PR → 通知 reviewer |

## 18. 底部状态栏（v0.4）

## 19. Ctrl+P 跳转文件（v0.5）

v0.5 起，新增 VS Code 风格的「快速打开文件」面板——按 `Ctrl + P`（Mac: `Cmd + P`）即可在工作区所有文件里模糊搜索并跳转。

### 19.1 打开方式

| 快捷键 | 行为 |
|---|---|
| `Ctrl + P` | 打开文件跳转面板 |
| `Ctrl + E` | 同上（VS Code 兼容） |
| `Ctrl + Shift + P` | 打开**命令**面板（v0.4+ 既有，不变） |
| 侧边栏底部「命令面板 ⇧P」按钮 | 打开命令面板（文件跳转需要用快捷键，v0.5 暂无独立按钮） |

### 19.2 使用流程

1. 按 `Ctrl + P` 打开面板（顶部 placeholder 变成"输入文件名跳转…"）
2. 键入文件路径片段（支持中文 / 中划线 / 点）
3. 列表实时过滤，按模糊匹配分数排序，**匹配的字符高亮**成绿色
4. 上下键移动高亮，Enter / 鼠标点击 → 跳转到该文件
5. 面板自动关闭，仓库页切到「文件」Tab，编辑器加载该文件

### 19.3 搜索算法

按"顺序子序列"匹配 + 多种加权：

- 输入"btn" → 匹配 `src/components/Button.tsx`（完整字符）
- 输入"src/cmp/btn" → 匹配 `src/components/Button.tsx`（按路径片段）
- 输入"chinese" → 匹配含 Chinese 注释的文件
- 不匹配时（如输入"zzzznotexist"）显示空结果提示

### 19.4 适用场景

| 场景 | 操作 |
|---|---|
| 在大仓库里快速找文件 | `Ctrl+P` → 输文件名前几字符 |
| 跳转嵌套子目录里的文件 | `Ctrl+P` → 输"父目录/文件"（不一定要输完整路径） |
| 知道文件名不记得路径 | `Ctrl+P` → 输文件名（按"文件名开头"加权排序） |

### 19.5 性能

5 千文件的仓库实测从打开到匹配结果 < 200 ms；10k+ 文件会一次性拉取 + 一次性模糊匹配（仍 < 500 ms）。后续 v0.5+ 考虑增量加载 / 流式。

> **提示**：命令面板（`Ctrl+Shift+P`）和文件跳转面板（`Ctrl+P`）共用同一个模态组件，UI 一致；只是顶部 placeholder 和结果列表内容不同。

## 20. 文件历史 + Blame（v0.5）

v0.5 起，编辑器上下文增强——能直接看到「这一行谁改的 / 这个文件经历过什么」。

### 20.1 Blame（行号 gutter 点击查询）

#### 触发

在 Monaco 编辑器打开文件后，**点击行号 gutter**（行号左侧 16px 区域）→ 屏幕右下角弹出浮窗，显示：

- commit hash（短 7 位 + emerald 绿）
- 作者 + 日期（YYYY-MM-DD）
- 当前行号
- commit message 第一行

再次点击任意处关闭。

#### 示例

1. 打开 `electron/services/git.ts`
2. 点击第 50 行的行号
3. 看到浮窗：`a3f7c9d · me · 2026-01-15 · 第 50 行 · feat(git): cherryPick 解析新 commit hash`

#### 适用场景

| 场景 | 操作 |
|---|---|
| 找某行代码谁改的 | 点行号 → 看浮窗 hash + 作者 + 时间 |
| 想知道 bug 引入时间 | 点行号 → 查日期 + 顺藤摸瓜看 commit |
| 复盘 code review | 点可疑行的行号 → 看引入者 |

### 20.2 文件历史（FileHistoryPanel 侧边抽屉）

#### 触发

编辑器顶部工具栏点击「历史」图标按钮（History 钟表回滚图标）→ 打开 560px 宽的右侧抽屉。

#### 抽屉内容

- 头部：文件路径 + 关闭 X
- 中部：commit 列表（最多 50 条，按时间倒序）
  - 每条：message 第一行 + 短 hash（emerald 绿）+ 作者 + 相对时间（"3 天前"）
  - 点击展开 diff（懒加载，第一次展开时调 fileDiff API）
- 展开后：自实现 diff 渲染（add/del 绿/红块，类似「变更」页的 DiffViewer 简化版）

#### 操作流程

1. 打开任意文件（如 `src/components/repo/BranchPanel.tsx`）
2. 顶部点「历史」→ 抽屉打开
3. 看到 30 条 commit（最近 → 最旧）
4. 点 "feat: PR 入口常驻" commit → 展开 diff → 看 +12 / -3 的代码变更
5. 再点同一行 → 折叠
6. 点 X 关闭抽屉

#### 适用场景

| 场景 | 操作 |
|---|---|
| 知道某 bug 引入时间但忘了 commit | 历史 → 看 commit 时间线 |
| 复盘「PR 入口」这次改动 | 历史 → 点对应 commit → 看 diff |
| 解释代码演进 | 历史 → 翻 commit list → 看 message |

### 20.3 性能 / 限制

- Blame 全量拉取 + 内存 Map 索引：5000 行文件 < 100ms
- 文件历史最多 50 条 commit
- Blame 不支持点击 hash 直接跳到历史 tab（v0.5 仅显示信息）
- 文件历史 diff 只显示当前文件，不显示 commit 的全部文件变更
- 二进制文件 Blame 不可用（git blame 默认行为）
