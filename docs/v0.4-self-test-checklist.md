## 3. Stash 队列（feat/stash）

> 准备：随便改一个文件但**不**暂存，作为 stash 测试内容

- [ ] 打开一个仓库，修改文件
- [ ] ChangesPanel 顶部出现「Stash 队列 (0)」折叠面板
- [ ] 点击面板标题 → 展开，显示「暂无 stash」
- [ ] 点击右上角 `+ 保存当前修改` → 出现输入框
- [ ] 输入描述如「测试 stash」→ 按 Enter（或点 OK）
- [ ] toast 显示「已保存到 stash」
- [ ] 列表出现一条 `stash@{0} @<branch>  N 分钟前`
- [ ] 工作区已清空（修改被存到 stash，状态栏「未暂存」变 0）
- [ ] 重新修改文件 → 点 Apply（hover 工具条上的回旋图标）→ 修改回到工作区
- [ ] toast 显示「已应用 stash@{0}（保留在队列）」
- [ ] 点 Pop（GitMerge 图标）→ 修改回到工作区 + stash 列表 -1
- [ ] 再次保存一个 stash → 点 View Diff（FileText 图标）→ 弹出 diff 浮窗
- [ ] diff 浮窗显示文件路径 + 增删行（绿/红配色）
- [ ] 关闭 diff 浮窗（点击 X 或外部）→ 关闭
- [ ] 点 Drop（Trash 图标）→ 浏览器 confirm 弹窗「确定从 stash 队列删除 stash@{0}？」
- [ ] confirm 取消 → 不删除
- [ ] confirm 确认 → 删除，列表 -1
- [ ] 在未打开仓库的状态下，**不**显示 StashList（不渲染）

## 4. Cherry-pick / Revert（feat/commit）

> 准备：在打开的仓库里，需要至少 2 个 commit，当前分支 HEAD 不在最前

- [ ] 切到「历史」tab（按 `2` 数字键也行）
- [ ] 鼠标移到任意一条 commit → 右侧 hover 工具条出现三个图标：Copy / Cherry-pick / Revert
- [ ] 点 Copy 图标 → toast「已复制 <完整 SHA>」，剪贴板验证
- [ ] 点 Cherry-pick → 弹出 CommitActionsModal
- [ ] Modal 显示 commit hash / 作者 / 提交说明
- [ ] 点「确定」→ toast「已 Cherry-pick <hash>」+ 弹出新 commit
- [ ] 点 Revert → 弹出 CommitActionsModal（标题含「危险」标识）
- [ ] 点「确定」→ toast「已 Revert <hash>」+ 弹出反向 commit
- [ ] **冲突测试**（可选）：尝试 cherry-pick 跟当前 branch 改动冲突的 commit → toast 黄色「Cherry-pick <hash> 产生冲突，请在「变更」页解决」

## 5. PR / MR 创建（feat/pr）

> 前置：在「设置」配置好 GitHub / Gitee Token，并确保有对应平台的真实仓库

### 5.1 创建入口可见

- [ ] 打开一个有 GitHub remote 的仓库
- [ ] **「分支」tab 顶部出现「创建 Pull Request」常驻按钮**（不在 hover 才出）
- [ ] 当前分支领先 0 commit 时，点按钮 → toast 黄色「当前分支没有领先远程的提交…」但仍打开弹窗
- [ ] 切到「仓库」主页（顶部）→ 顶部工具栏也出现「创建 PR」按钮（同一仓库的第二个入口）

### 5.2 创建流程

- [ ] 点「创建 Pull Request」→ 弹出 CreatePRDialog
- [ ] 平台选择区显示该 GitHub 仓库（GitHub icon + `owner/repo`）
- [ ] 选中平台后自动拉默认 base 分支（如 `main`），加载完显示在「目标分支」输入框
- [ ] 默认 base 拉取失败时降级显示 `master`
- [ ] 标题自动填入最后一次 commit 的 subject（`log[0].message` 第一行）
- [ ] 编辑标题、描述、勾选「创建为草稿」（GitHub only）
- [ ] 点「创建 PR」→ 调 GitHub API
- [ ] 成功页显示 htmlUrl + 「在浏览器打开」按钮
- [ ] 点「在浏览器打开」→ 系统默认浏览器打开 PR 页面
- [ ] 失败时 toast「创建失败：<error>」，不进入成功页

### 5.3 无可用平台

- [ ] 切到一个只有 GitLab remote 的仓库（`url: https://gitlab.com/...`）→ 弹窗显示「没有可用的 GitHub / Gitee 远程仓库」+ hint
- [ ] 无任何 remote 的仓库 → 同上

### 5.4 Gitee 端到端

- [ ] 同上流程在 Gitee 仓库上跑一遍（默认 base 应为 `master`，不显示 Draft 复选框）
