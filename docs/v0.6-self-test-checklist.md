- [ ] 已配 Token 时列出已有 release；没配时显示「未配置 GitHub Token / Gitee Token」

## 3. 新建 Release（v0.6 P0.2 — 重点）

### 3.1 基本流程

- [ ] 点「+ 新建 Release」展开表单
- [ ] 输入 tag (v0.6.0) + name + Markdown body
- [ ] draft / prerelease 复选框：Gitee 平台下 draft 自动禁用
- [ ] 必填校验：tag 和 name 为空时点「创建」→ toast 提示
- [ ] 点「创建」→ toast「已创建 Release」→ 列表自动刷新，新 release 出现

### 3.2 附件上传（重点）

- [ ] 附件区：点「添加附件」→ 系统多选对话框弹出
- [ ] 选 1-3 个本地文件（zip / txt / pdf / exe 都行）→ 列表显示文件名
- [ ] 点文件右侧 × → 从列表移除
- [ ] Gitee 平台下添加 ≥100MB 的文件 → 触发 amber 提示「Gitee 单附件上限约 100MB，建议使用 GitHub」
- [ ] 点「创建」后：
  - 先创建 release（toast「已创建 Release」）
  - 再逐个上传附件（无中间 toast，最终 toast「已创建 Release 并上传 N 个附件」）
  - 任一附件失败 → 该附件 toast warn，其他继续（最终 toast 反映「N/M 上传成功」）
- [ ] 列表出现新 release，详情抽屉打开后附件完整显示

### 3.3 CHANGELOG 自动生成

- [ ] 点「从 commits 自动生成 CHANGELOG」→ body 自动填入
- [ ] 之前填的 body 不丢失（CHANGELOG 按钮只追加/替换）

## 4. 详情抽屉（v0.6 P0.3 — 重点）

### 4.1 入口

- [ ] 点任意 release 卡片的「详情」按钮（`>` 图标）→ 右侧 640px 抽屉滑入
- [ ] 抽屉头部：tag / name / 状态徽标（草稿/预发布/平台）/ 发布时间
- [ ] body 区用 **marked 渲染 Markdown**：
  - 标题（`#` / `##`）渲染成 `<h1>` / `<h2>`
  - 列表（`-`）渲染成 `<ul><li>`
  - 代码块（` ``` `）渲染成 `<pre><code>`
  - 链接（`[text](url)`）渲染成 `<a>`
- [ ] body 为空时显示「（无描述）」
- [ ] Esc 关闭抽屉

### 4.2 附件管理（重点）

- [ ] 附件区：每个附件一行（`📦 name` + 大小 + 下载次数 + 下载按钮 + 删除按钮）
- [ ] 大小 / 下载次数显示正确（GitHub / Gitee 都对得上）
- [ ] 点下载按钮 → 系统下载附件到默认目录
- [ ] 点删除按钮 → 二次确认「确定删除附件 {name}？」 → toast 成功 → 列表实时更新

### 4.3 上传新附件（重点）

- [ ] 抽屉附件区点「上传新附件」→ 系统单选对话框弹出
- [ ] 选 1 个本地文件 → toast「已上传 1 个附件」→ 列表实时刷新新行
- [ ] 可重复点「上传新附件」继续追加

## 5. 编辑 Release（v0.6 P0.4 — 重点）

- [ ] 抽屉底部点「编辑」→ 切换到编辑模式（name input + body textarea + prerelease checkbox）
- [ ] 改 name（如「Release v0.6.0 — 正式版」）→ 点「保存修改」→ toast 成功 → 抽屉切回查看模式，新 name 显示
- [ ] 改 body → 「保存修改」→ body 重新渲染，新内容显示
- [ ] 勾选/取消 prerelease → 「保存修改」→ 列表徽标同步
- [ ] 编辑模式下按 Esc 取消（不保存，恢复原内容）
- [ ] Gitee 平台下编辑不应有「草稿」复选框（不支持）

## 6. 发布草稿（v0.6 P0.5）

- [ ] 列表卡片显示「草稿」徽标 + 出现「发布草稿」按钮
- [ ] 抽屉内底部也出现「发布草稿」按钮

## 10. 已知 v0.6 限制 / 未实现

- [ ] 附件上传无进度条（v0.7 候选）
- [ ] Markdown sanitize 启动自检在 `happy-dom` 等非完整 DOM 环境会判定为「不可信」并降级为纯文本渲染（实测 DOMPurify 3.4.14 在 happy-dom 下会静默失效；详见 `docs/features.md` §22.2.8）
- [ ] Gitee 单附件 ≤ 100MB（平台限制；建议大文件用 GitHub）
- [ ] 错误消息路径脱敏在某些边角场景下可能过度（保留最后两段是 90% 场景的最优解，但纯路径无文件名的报错会丢失上下文；详见 `docs/features.md` §22.9）
- [ ] 设置页"选择 SSH 私钥"用 `prompt` 而不是文件选择对话框（项目里 `fs:*` 通道都是目录接口，"选单个文件"的 IPC 还没有；详见 `docs/features.md` §23.5）
- [ ] `preferredProtocol: 'ssh'` 模式当前不做"自动改 remote + push + 还原"的临时切换（v0.7 候选）
